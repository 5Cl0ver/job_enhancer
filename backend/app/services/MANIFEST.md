# Services Manifest (`backend/app/services/`)

Business-logic layer — async functions, no FastAPI objects. Routers own the
transaction boundary (services `flush`, routers `commit`).

| File | Purpose | Key functions |
|---|---|---|
| `users.py` | User lifecycle | `create_user()` (seeds default collection + 8 pipeline stages; admin if email==ADMIN_EMAIL), `soft_delete_user()`, `purge_deleted_users()` (scheduled) |
| `dedup.py` | Listing dedup | `normalize()`, `job_content_hash()` (SHA-256), `is_duplicate()` (rapidfuzz: title ≥88, company ≥85) |
| `job_search.py` | Multi-source search | `aggregate_and_deduplicate()` — fetch Adzuna + JSearch in parallel, parse, dedupe, upsert, paginate; `mark_expired_listings()` (scheduled). **Being refactored to a pluggable adapter + cache model — see [docs/job-data-architecture.md](../../../docs/job-data-architecture.md)** |
| `collections.py` | Collection CRUD | create/list/update/delete (blocks default) |
| `scout_runs.py` | Claude Scout searches and runs | missions CRUD, `queue_run`, `runs_out`, `record_capture` (extension); connector side: `brief`, `check_jobs` (which rows are new; remembers the rows Claude passed over by title for that resume type for 30 days; hands out the next results page's link, up to 4 pages a run), `report_job` (a good fit becomes a pick that waits for the user, or is saved at once when the search says "without asking"; always from the captured page copy, never Claude's text), `missions_out`, `finish_run`. `search_titles` / `search_links` (each title and related title its own plain-words search, up to the searches-per-run limit, taking turns; exact titles share one quoted search), `board_radius` (any radius rounded up to the board's options; 25 by default with a place), `page_url` (next page of one search), `dropped_params` / `link_report` / `links_line` (each search's result count and filters the board dropped), `run_tip` (what to change when a search came back short); keep going (spec 021): a run still short once its searches are read adds remote searches, then the past 14 days, then the titles it left out (`_keep_going`, criteria `more`/`steps`), until the "looks" limit of jobs; `_link` writes Google's searches as "near {place}" plus the window in words and each board's remote search; `_with_state` gives a bare town its state from the application profile (criteria `where`); `looked_line` reports the jobs looked through; `set_search_titles` and the broad parts of `brief` / `report_job` for the "Anything I'd be good at" search; `resume_ready` (every run tells Claude to read the resume via `get_master_profile`). Replies never grow with the tracker (spec research R8) |
| `allowance.py` | Fair use of the shared free services (spec 019 part C) | `spend` (before the paid call; 429 `ALLOWANCE` when over, nothing spent; admins counted, never stopped), `refund`, `spending` (context manager: give back on failure), `jsearch_take` (shared month, owner reserve), `usage`, `usage_by_user`, `limits` / `save_limits` / `validate`, `purge_old_usage` (scheduled, 400 days) |
| `onboarding.py` | The Welcome and Getting started (spec 019 part B) | `get_or_create`, `state` (ticks worked out from real state: résumé, profile reviewed, Job Catcher said hello, a saved job, email, Claude), `patch`, `touch_claude` (hourly, never raises) |
| `scout_review.py` | Claude Scout's review step: Claude proposes, the user decides | `resolve_folder` / `peek_folder` (which collection: chosen on the save, on the search, or named after the resume type), `save_finding_job` (from the page copy only), `confirm_run` (save what was ticked; unticked picks become "skipped"), `save_one` (from History), `count_to_review` |
| `skipped_sites.py` | Sites to skip (spec 024) | `host_of` (the site from a pasted link or name; None when it isn't one), `matches` (the site or a real sub-site, never a look-alike), `skipped_by` (a link's skipped site), `hosts` / `list_sites`, `add` (400 not a site, an application system many companies use (`APPLICATION_SYSTEMS`: Greenhouse, Lever, Workday…), a shared name ("co.uk", github.io…) or over 100; 409 `needs_confirm` for LinkedIn, Indeed, ZipRecruiter, Google until confirmed; already-covered sites aren't added twice, and two adds at once give "already"), `remove`, `suggestions` (known reposting sites seen in the user's own Scout finds, never added on their own), `refusal` / `apply_refusal` (what Claude is told). Hosts are lowercase, no "www.", international names in xn-- form. Read live by `scout_runs` (brief `skip_sites`, `check_jobs` `skipped_site`, `report_job`) and `apply_runs` (`apply_url_skipped`; `fill_request` / `page_done` refuse a page on a skipped site) |
| `scout_instructions.py` | Everything Claude Scout tells Claude, and the user's edits (spec 010) | originals from `app/scout/*.md`; `sections`, `save` / `reset` / `restore` / `history` (20 versions), checks (8,000 characters, scoring adds up to 10, limit ranges); `snapshot` (a run's own copy at Start), `assemble_playbook` (the user's steps, the scoring line, then the locked `rules.md`), `limit` |
| `scout_log.py` | The run log (spec 010) | `record` (one connector call: plain summary, what Claude sent, the app's answer or refusal, trimmed to 8,000 characters, at most 400 a run), `record_resume_read` (the fact only), `brief_view` (instruction texts referenced, not repeated), `events` |
| `scout_titles.py` | The titles an "Anything I'd be good at" search tries (spec 009) | `choose` (Always first, never a Never or resting title, at most 8), `record_runs`, `credit_fit` (the searched title with the most words in common), `tried`, `for_brief`, `is_resting` (3 runs with no good fit → 14 days) |
| `scout_companies.py` | Claude Scout's "Local companies" search (no job boards) | `check` (which businesses from a Google search to visit: new ones, plus up to 3 checked a week or more ago, openings first; never job boards, directories or ones the user skipped; at most 15 a run), `checked` (what a company's careers page had; "not_checked" when the site couldn't be checked, due again next run), `rechecks` (for the brief), `summary`, `site_key`; the page's `list_companies` / `update_company` (check next run, never check) |
| `scout_dedupe.py` | Claude Scout keys (pure) | `company_key`, `title_key`, `url_key` (one key per posting across tracking params/side panes), `posting_problem` (search/home pages, Google pages), `posting_link`, `is_job_site` (boards, directories, review sites) |
| `scout_tracks.py` | Claude Scout resume types | list/create/update/delete (≤8, unique names, own resumes only; delete untags jobs), `to_out()` adds file name + job count |
| `resume_history.py` | A résumé read ONCE into work history + education (stored on `resumes.parsed_history`); read after upload or when the bundle finds it missing (spec 015) | `read_resume()`, `history_of()`, `read_in_background()`; spec 029: details carry `reader` (the reader's version) or `edited` (the user's, never replaced by a reading); `upgrade()` reads a pre-029 reading again once when its jobs are still exactly the old reader's (`resume_reader_v1`), and marks it either way; `upgrade_active()` (the bundle) |
| `autofill_bundle.py` | Everything Job Catcher's autofill needs in one answer, behind a cheap version check (spec 015) | `bundle_version()`, `build_bundle()` — served by `GET /v1/autofill/bundle` |
| `saved_jobs.py` | Saved-job CRUD | `save_job()` / `save_manual_job()` (both record `origin`: how the job got here), `scout_fits()`, `rename_listing()` (the user's own name, place and link, kept on their saved job and shown in place of the shared listing's, which is never edited), `own_names()`, `doubtful_names()`, `list_saved_jobs()`, `update_saved_job()` (tracks `last_stage_change`), `delete_saved_job()` |
| `job_links.py` | Tie an email to the saved job it's really about | `link_job()` / `unlink_job()` ("Same job as…": fold a job made from an email into the real one, card forward only, with Undo), `link_event()` / `unlink_event()` ("Pick the job" on an unsaved update, and "Wrong job", which is remembered in `not_jobs`), `promote_unsaved()` + `place()` (after each scan, put updates that fit exactly one saved job on it: exact company, same role, not from long before the job was saved), `rank_jobs()` (the picker's order). Never reads the email body. User-scoped |
| `email_scan.py` · `email_match.py` · `email_recheck.py` (spec 027) | Every email about a saved job is kept | `detect_events` stores an email whose card needs no move as `noted` (on the job, never thrown away) and job-looking emails not put on a job as `skipped` (+`skip_reason`) for "Looked at, not shown"; `looks_like_digest` counts separate title mentions and distinctive company names only, and runs after matching (`clearly_one_job` from the company, not a job board, is never an alert); `email_recheck` re-reads N days in the background (empty cursors, stored emails skipped, no card moved); `email_review.purge_looked_at` keeps 30 days / 500 |
| `job_source.py` | Where a saved job came from | `job_source()`: its collection, plus the Claude Scout search (fit, why, gaps, run) or the email it was made from. Read-only, user-scoped |
| `saved_searches.py` | Saved searches + matches | create/list/delete, `refresh_saved_searches()` (scheduled), new-matches feed (FR-024) |
| `tracker.py` | Kanban stages | `seed_default_stages()`, stage CRUD, `move_job_to_stage()` (sets `applied_at` once on "Applied") |
| `notifications.py` | Reminders | `send_follow_up_reminders()` (scheduled hourly) |
| `resume_parser.py` | Resume text | `parse_resume_pdf()` (pdfplumber), `parse_resume_docx()` (python-docx) |
| `ai_service.py` | NVIDIA NIM | `generate_tailored_resume()`, `generate_cover_letter()` → `(content, model_used, generation_ms)`; handles 429 |
| `admin_service.py` | Monitoring | `get_platform_stats()`, `check_service_health()` (pings DB/NVIDIA/Adzuna/JSearch) |
| `apply_runs.py` | Apply with Claude (spec 022): one application, start to finish | `create_run` (one open run a user; `RunBusy`), `open_run` (runs idle 3 h stop), `view`; connector side: `brief`, `ask_questions`, `record_answers` (each answer kept as a thing told to Claude), `save_resume`, `fill_request` / `page_done` (a request Job Catcher claims; the tool waits ≤45 s in `wait_request`), `photo_result`, `need_help`, `wait_for_you` (answers / keep going / review decision), `user_said` (what the user said in a chat), `decide`, `finish` (sent only after the user's OK; job → Applied); Job Catcher side: `extension_state` (requests + Submit `guard`), `claim`, `add_photo` (JPEG ≤400 KB, ≤8 a page), `finish_request`, `extension_event` (blocked / pressed Submit); `purge_old_photos` (30 days after a run ends); spec 023 "apply from the app": `post_message` / `message_user` / `inbox` / `with_inbox` (the conversation; every tool result carries what the user wrote), `need_help` quick answers + a photo of the screen, `help_done(reply)`, `peek` (screen now, newest 5 kept), `claude_stopped`, `ask_if_sent`, `not_sent`, `confirmation_seen` (sent, confirmed), `job_catcher_status` (ready = 0.41.0+, seen in 2 h); spec 025: `create_run(resume_id)` (a picked résumé skips questions, writing and the look), the `resume_review` status after `save_resume` (unless `users.review_resumes` is off), `resume_decide` (use / change + note, from the app or a chat); spec 026: `extension_state.resume_id` (the run's résumé for Job Catcher, never a URL guess), `save_live` (the live view: Job Catcher's reading of the page being filled, sensitive boxes dropped, cleared when filling ends), answers marked `guess` / `agreement` / `by: job_catcher`, `fill_result.resume` in plain words, photo reasons in plain words, `decide(fixes=…)` (the answer bubbles' changes and questions, sent together); spec 029: `decide` submit/self learns Claude's answers (`apply_learn`), fixes are remembered in `review.changed`; spec 030: `ask_questions` as one checklist (`guess`, `choices`, `only_you`, `batch`; ≤12 at once, ≤30 a run; while filling too, then back to filling), `open_batch`, `live_fix` (a change while filling: the user's words as an unread message, the box from the live view kept apart in `fix` as page text; the inbox note says what to do), answers go back to where asking began (`from`), a kept guess (`guessed`) isn't a thing told, `report_problem`; spec 031: `save_cover_letter` (the job's letter only when the user hasn't chosen another or None; never moves the step), the job's `cover_letter` in `view`, `cover_letter_text` in the brief, `cover_letter_id` in Job Catcher's state |
| `apply_problems.py` | Problems Claude ran into during a run (spec 030) | `scrub(text, cap=500, lines=False)` (passwords, "password X", codes, emails, phones, card numbers, SSNs, key blobs removed, also when split across a line break; removed first, then capped; shared by Bugs & ideas), `page_of` (no query; job slugs kept), `add` (kinds checked, short id, context: run, job, site, Job Catcher and playbook versions; same one counted and open again; ≤20 a run; returns what it kept, for the inbox) |
| `bug_reports.py` | Bugs & ideas (spec 032): every rule of the owner's inbox | `create`, `list_reports` (tab, filters, search, priority: pinned, severity, came back, count, last seen; section counts), `detail` (events, links, shots, run, job), `update_report` (any field; statuses per type; Claude's fix needs the owner's check; bug ↔ idea), `bulk`, `delete_report`, `add_note`, `link` / `unlink`, `merge` / `split` (split works the dates out again from the report's own and what's still merged in), `from_run_problem` (a run's problem as a report; `run_fingerprint`, unique, so two at once are one report; counts go up in SQL; a fixed one comes back as new), `count_new_bugs`, `clean_place` (no query; ids and token-like segments as `:id`); `detail` says whether the run and job are the viewer's own (`own`). Never stores who; every text scrubbed and capped |
| `apply_resume.py` | A résumé made for one job (spec 022) | `check_layout` (name heading + sections), `save_for_job` (a document + a PDF résumé set as the job's résumé; its jobs, schools and skills read from its OWN text by `history_of_document`, spec 029), `rerender` (an edit remakes the PDF, and its details unless the user edited them), `refresh_borrowed` (a job's résumé saved before 029 still carrying the master's details is read again from its document, once; edited details are kept), `forget_resume` (delete; jobs go back to the usual one) |
| `cover_letters.py` | Cover letters, like résumés (spec 031) | `check_letter` (Claude's: 150 chars–~250 words, no header, no "Dear …" / "To whom it may concern" / "I am writing to express", no [placeholders]), `check_edit` (the user's: ≤10,000 chars), `save_for_job` (a `cover_letter` document recorded on the run; it becomes the job's only when the job has none yet or still has this run's earlier letter, so the user's pick or "None" always wins; a second save in the run replaces it), `set_for_job`, `listed`, `pdf_of` (drawn on demand in the résumé's look: the job's made résumé header, else the profile's name and contact; the date; the letter) |
| `apply_learn.py` | Learning from Claude's runs (spec 029) | `learn` (on the user's Submit / "I'll submit it myself": facts Claude wrote (`claude: true`, never a `guess`) for boxes Job Catcher didn't fill become `custom_answers` with `source="claude"`; never over the user's own, never a key the user deleted), `candidates` (never passwords, private numbers, self-ID, agreements (Job Catcher's CONSENT), essays or answers over 300 characters, criminal / citizenship / visa / sponsorship / work authorisation / clearance, pay, relatives, former employees or questions naming the company, the user's own details, or anything changed at a review or between rounds), `answer_text` (a list as "A, B"), `forget` / `unforget` (`users.forgotten_answers`), `note_changes` (`review.changed`, kept across rounds; spec 030: reads `box_on_page`, and `changed_questions` also counts boxes changed while Claude filled), `normalize` (= Job Catcher's `normalizeQuestion`) |
| `resume_reader.py` | A résumé read without AI (spec 020) | `read(text)` → `{work, education, skills, certifications, websites}`; spec 029: a PDF's wrapped lines joined back into their sentence, points split only at a bullet or a sentence end (a line starting with a verb of work done is a new point), "• " kept, never cut mid-word; a line ending or carrying on a sentence is never taken as the next job's name; the company (or title) on the line under "Title  dates", only when it reads like a name (capitalised words, at most six; "Bank of America" yes, "Team lead for payments" no); a verb-like first word followed by a capitalised one on a short line is a name ("United Rentals") |
| `resume_reader_v1.py` | The pre-029 job reader, frozen | `work(text)`: only to tell whether stored jobs are still exactly what it made (never edited) |
| `master_profile.py` | What Claude writes from (spec 022) | `master_resume` (the master, else the usual), `facts` (things told to Claude), `profile_text` (profile + saved answers + facts + master résumé) |
| `apply_playbook.py` | Claude's steps for an application | `playbook_text` (`app/apply/playbook.md` + the locked `rules.md`), `APPLY_PLAYBOOK_VERSION` (2026.11.29, spec 029: apply links open in the same tab; 2026.11.30, spec 030: one checklist, mid-fill changes, report problems; 2026.12.01, spec 031: cover letters only when asked) |
| `resume_pdf.py` | The PDF maker (moved from `api/v1/ai.py`), drawn in the owner's master résumé template (spec 025) | `render_pdf(markdown)` — fpdf2, Carlito, US Letter: navy name + rule, blue `> title line`, grey contact, section headings on a light-blue rule, `**Label:** items` as a two-column skills table, job headers (`**Title** · Company \| dates` or the older `**Company** \| *Title* \| dates`) with dates on the right, blue `### Group` sub-headings, `## CORE AREAS` boxes, "Page X of Y" (2+ pages); the colors and sizes are constants at the top. Cover letters get the same header; `render_letter_pdf(header, body, date)` draws a letter (spec 031): the résumé header, then the date and plain paragraphs. Never fails: anything the template can't lay out comes out as plain text |

**Scheduled jobs** (registered in `app/main.py` via APScheduler): follow-up
reminders (hourly), saved-search refresh, listing expiry, deleted-account purge (daily).

**How this folder connects:** called by `api/v1/*`; operates on `models/*`;
never imports from `api/` (no circular deps).
